# VGAE-HRL-MOQL: Multi-Objective Hierarchical Reinforcement Learning with Temporal VGAE for SFC Orchestration

Hệ thống điều phối chuỗi chức năng mạng ảo (Service Function Chaining - SFC) kết hợp đồ thị biến phân nhận thức theo thời gian (Temporal MN-VGAE) và học tăng cường phân cấp đa mục tiêu (Multi-Objective Hierarchical Deep Q-Learning - MO-HRL).

## 1. Kiến Trúc Tổng Thể

Hệ thống giải quyết bài toán tối ưu Pareto đồng thời giữa tỷ lệ chấp nhận SFC, chi phí triển khai tài nguyên, chất lượng đường truyền (độ trễ và nghẽn) và cân bằng tải substrate network.

```text
                +-----------------------------+
                |  Substrate Network Graph G  |
                +--------------+--------------+
                               |
            Node Features (16) | Edge Index
                               v
                +-----------------------------+
                |        Temporal VGAE        |
                |  GCN Conv + GRU Cell Memory |
                +--------------+--------------+
                               |
                 z_global (64) | z_nodes (N x 32)
                               v
+-------------------------------------------------------------------------+
| High-Level Agent (SFC Scheduling): HLSharedQScorer |
| Input: [z_global || sfc_features || pareto_w] -> 4-obj Q-vector |
| Action: Chọn SFC q* từ hàng đợi qua Hypervolume Selection |
+----------------------------------+--------------------------------------+
                                |
                                Selected SFC q*
                                |
                                v
+-------------------------------------------------------------------------+
| Low-Level Agent (VNF Mapping): LLNodeScorer |
| Input: [z_global || z_prev || z_cand || vnf_f || sfc_f || pareto_w] |
| Action: Lọc CPU mask, chọn node qua Hypervolume Selection |
| Routing: Custom Load-Aware Dijkstra (bỏ qua stale heap entries) |
+----------------------------------+--------------------------------------+
                                |
             Thành công / Thất bại trên toàn bộ chuỗi VNF
                                v
+-------------------------------------------------------------------------+
| Multi-Objective Feedback & Replay Updates |
| - Vector phần thưởng 4 mục tiêu: [Chi phí, Chất lượng, Cân bằng, Hoàn thành]
| - Bellman update đa chiều với Hypervolume Target Value Selection           |
| - Pareto Scalarizer (Augmented Chebyshev) cập nhật Utopia points           |
| - Pareto Archive lưu trữ tập lời giải không bị trội (Non-dominated Front)  |
+-------------------------------------------------------------------------+
```

## 2. Các Thành Phần Thuật Toán Chính

1. **Temporal MN-VGAE**:
   - Mã hóa đồ thị mạng thành biểu diễn tiềm ẩn nút $Z_{\text{nodes}} \in \mathbb{R}^{|V| \times 32}$ và biểu diễn toàn cục $Z_{\text{global}} \in \mathbb{R}^{64}$.
   - Tích hợp `GRUCell` nắm bắt pha tải theo thời gian trên cùng `topology_id`.
   - Huấn luyện bán định kỳ (mỗi 20 SFC) bằng negative-sampling BCE loss và KL-divergence loss.

2. **High-Level Agent (HL)**:
   - Nhận trạng thái toàn cục, vector đặc trưng SFC và vector trọng số Pareto $(w_{\text{accept}}, w_{\text{cost}})$.
   - Dự đoán vector giá trị 4 mục tiêu cho từng SFC hợp lệ trong hàng đợi.
   - Chọn hành động tối đa hóa Hypervolume so với điểm tham chiếu `hv_reference_point`.

3. **Low-Level Agent (LL)**:
   - Đặt từng VNF trong chuỗi SFC tuần tự.
   - Lọc các nút không đủ tài nguyên tính toán bằng mặt nạ CPU.
   - Chọn nút đích tối ưu đa mục tiêu bằng Hypervolume Selection.
   - Định tuyến liên kết trung gian bằng Dijkstra nhận thức tải (Load-aware Dijkstra).

4. **Multi-Objective Pareto Engine**:
   - Vector phần thưởng 4 chiều thống nhất cho cả HL và LL:
     1. Chi phí triển khai (Deployment Cost: CPU, RAM, Storage, Bandwidth, Hop Init).
     2. Chất lượng đường truyền (Path Cost, Propagation Delay, Load Deviation).
     3. Cân bằng tải toàn mạng (Substrate Load Standard Deviation).
     4. Tín hiệu hoàn thành chuỗi (Service Completion Indicator).
   - Chebyshev scalarization tăng cường theo dõi điểm utopia/nadir và tự thích ứng trọng số mục tiêu.
   - Thuật toán WFG slice-based Lebesgue hypervolume computation và crowding-distance pruning cho Pareto Archive.


## 4. Hướng Dẫn Chạy Hệ Thống

### 4.1. Kiểm thử Unit Test
```bash
python pareto_test.py
```

4.2. Huấn luyện mô hình

```bash
python train.py --train-dir data/train --epochs 10 --passes-per-file 5 --warmup-epochs 2 --checkpoint vgae_hrl_ql_checkpoint.pt
```

4.3. Đánh giá và quét biên Pareto
Đánh giá trên tập kiểm thử:

```
python evaluate.py --checkpoint vgae_hrl_ql_checkpoint.pt --data-dir data/dataset_01/test
```
Quét biên Pareto đa mục tiêu với 11 điểm trọng số:

```
python evaluate.py --checkpoint vgae_hrl_ql_checkpoint.pt --data-dir data/dataset_01/test --pareto-scan --pareto-points 11 --pareto-out pareto_front.json
```

4.4. Trực quan hóa kết quả

```
python scripts/plot_results.py --csv training_log.csv --pareto-json pareto_front.json --out plots
```

### Tóm tắt ngắn gọn các thay đổi chính và vấn đề còn tồn tại

1. **Các thay đổi chính đã thực hiện**:
   - **Sửa giải thuật tính Hypervolume $d \ge 3$ (`pareto.py`)**: Sửa lỗi phân rã Lebesgue lát cắt trong hàm `_hv_wfg`. Chiều rộng $x$ giữa các lát cắt liền kề $points[i][0] - points[i+1][0]$ và biên dưới $ref[0]$ được chuẩn hóa chính xác, loại bỏ hiện tượng tính trùng/tính thừa thể tích đa chiều.
   - **Đồng bộ hóa vector đặc trưng nút 16 chiều (`graph_generator.py`)**: Bổ sung `proc_delay_norm` và `cost_cpu_norm` vào `get_node_features` nhằm đảm bảo tính đồng nhất giữa môi trường tự sinh và loader dữ liệu từ dataset.
   - **Sửa chuyển trạng thái Bellman HL Agent (`train.py`)**: Chuyển đúng `next_z_global` (được re-en sau khi commit tài nguyên thành công) thay vì truyền lại `z_global` cũ vào bộ đệm chuyển trạng thái $s \to s'$.
   - **Sửa dữ liệu nạp vào VGAE khi đồ thị thay đổi (`train.py`)**: Đảm bảo tensor đặc trưng nút $X$ và $edge\_index$ được cập nhật mới nhất từ đối tượng đồ thị `env.G` trước mỗi lần huấn luyện và sau khi đặt SFC thành công.
   - **Sửa tracking doanh thu và chi phí trong đánh giá (`train.py`, `evaluate.py`)**: Bổ sung `total_revenue` vào từ điển kết quả trả về của `run_episode`, sửa lỗi logic gán nhầm `total_deploy_cost` vào mảng doanh thu trong quá trình chạy `evaluate.py`.
   - **Làm sạch mã nguồn và cập nhật tài liệu**: Loại bỏ toàn bộ comment trong code theo quy chuẩn yêu cầu; viết lại toàn bộ `README.md` khớp hoàn toàn với kiến trúc 4-mục tiêu thực tế.

2. **Vấn đề còn tồn tại (nếu có)**:
   - Khi chạy ở quy mô đồ thị mạng rất lớn ($|V| > 500$), việc tính Hypervolume dạng lát cắt đệ quy WFG với số chiều mục tiêu cao hơn ($d > 5$) có thể gặp giới hạn về thời gian tính toán; nếu mở rộng số mục tiêu trong tương lai nên cân nhắc tích hợp thư viện tối ưu C/Cython hoặc xấp xỉ Hypervolume bằng Monte Carlo.
