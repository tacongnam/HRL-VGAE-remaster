# DRL-NFV: Pareto Q-Learning với Hypervolume trong HRL

## Kiến trúc tổng thể

```
VGAE (graph encoder)
  ↓ z_nodes, z_global
HRL
  ├── HL Agent — Admission + SFC selection
  │     └── Pareto Q-set + Hypervolume action selection
  ├── LL Agent — Node placement
  │     └── Pareto Q-set + Hypervolume action selection
  └── Routing — Dijkstra (giữ nguyên)
```

Pipeline mỗi SFC:

```
VGAE encode → HL chọn SFC → LL đặt VNF (k=1..K) → Dijkstra route → commit/rollback
```

---

## Thay đổi so với phiên bản scalar DQN

| Thành phần | Cũ | Mới |
|---|---|---|
| Q-value | scalar Q(s,a) ∈ ℝ | Q-set(s,a): list of 4-dim vectors |
| N objectives | 2 | 4 |
| Action selection | argmax(weighted sum) | Hypervolume score |
| Bellman target | scalar TD | TargetSet = ND(∪ next Q-sets) |
| Tie-break | weighted sum | violations → norm cost → seeded random |
| Failure reward | scalar -r_fail | failure_penalty_vector [4-dim] |
| valid_action_mask | không có | lưu trong replay buffer |

---

## Các mục tiêu (objectives)

Tất cả 4 objectives đều **maximize** trước khi so sánh Pareto:

```
r_vec = [r_cost, r_delay, r_resource_balance, r_success]
```

| Index | Tên | Giá trị | Quy ước |
|---|---|---|---|
| 0 | r_cost | `-mu_deploy_cost * deploy_cost` | maximize = minimize cost |
| 1 | r_delay | `-(alpha*path_cost + beta*path_delay + gamma*load_std)` | maximize = minimize delay |
| 2 | r_resource_balance | `-load_std` | maximize = cân bằng tải |
| 3 | r_success | `1.0` khi OK, `-p_success` khi fail | maximize = tỷ lệ thành công |

**Failure penalty vector** (tất cả âm, cấu hình trong `ParetoConfig`):
```python
failure_penalty_vector = [-p_cost, -p_delay, -p_balance, -p_success]
```

## Hypervolume action selection

### Công thức

```
HV_score(a) = HV(ND(Q_set(s, a)), reference_point)
```

### Reference point

Cố định trong config (`ParetoConfig`), nhất quán giữa các episode:

```python
hv_reference_point = [hv_ref_cost, hv_ref_delay, hv_ref_balance, hv_ref_success]
# Mặc định: [-1.0, -1.0, -1.0, -1.0]
```

Reference point phải nằm kém hơn mọi giá trị hợp lệ theo tất cả objectives.

### Tie-break (3 cấp)

1. Action có ít rủi ro vi phạm ràng buộc hơn.
2. Action có `mean(Q_set[:,0])` cao hơn (cost objective).
3. Random có seed cố định (`random.Random(cfg.train.seed)`).

### Bellman update (Q-set)

```
TargetSet(s, a) = ND({r_vec + γ * q_next
                      for q_next in ND(∪ Q_set(s', a'))
                      for a' in valid_next_actions})
```

Nếu `|TargetSet| > M`, áp dụng `prune_by_hypervolume()`. `M = cfg.qnet.max_q_vectors_per_action`.

## Hệ thống đang dùng

```
Placement: Multi-objective Pareto Q-set + Hypervolume action selection  [MỚI]
Admission:  Scalar Chebyshev scalarizer (PPO-GRU — không thay đổi)      [GIỮ NGUYÊN]
```

Admission PPO-GRU sử dụng scalar reward hiện tại, KHÔNG được thay đổi trong phiên bản này.

  --train-dir data/train \

## Giới hạn và lưu ý

- HV 4D dùng thuật toán WFG đệ quy — `O(n^{d-1} log n)`. Với `M=10` không đáng kể.
- `prune_by_hypervolume` gọi `hypervolume_contribution` mỗi vòng → `O(M^2 * HV_cost)`. Ổn với M nhỏ.
- Reference point cố định trong config. **Không tự động thay đổi** — đảm bảo HV so sánh được qua episodes.
- Trong warmup (`epsilon=1.0`), HV không được gọi (random selection). AccRatio warmup giống scalar DQN.
- `r_H` (Chebyshev scalar cho logging) tính từ `(r_accept_component, r_cost_component)` — **không** từ `failure_penalty_vector` để đảm bảo tương thích với phiên bản cũ.
